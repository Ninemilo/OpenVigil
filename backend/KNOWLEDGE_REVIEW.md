# PDF 原件对照与数值复核

该功能为已验证 PDF 段落提供独立的人工复核记录。原件、OCR 摘录、原始哈希及检索向量保持不变；复核结果不授予作业许可，也不替代领域专家或现场验收。

## 使用流程

1. 在知识库文档或引用详情中选择一个段落，点击“对照原件”。桌面并排显示 PDF 和解析原文，窄屏上下排列。
2. 浏览器下载后再次核对原件 SHA-256、文档版本、段落和页码，再以本地 PDF.js worker 渲染。读取失败、超限、链接过期或哈希不一致时停止预览，可显式重试或重新获取授权。
3. 展开“数值复核”。选择“确认原数值”，或在原摘录中选择完整数值，填写修正值、明确单位及说明。单位变化必须指向原文相邻的单位位置，不会自动进行单位换算。
4. 提议进入待复核。另一个具有当前范围权限的运维经理或维护复核人核对相同原件后，填写说明并批准或拒绝；提议人不能批准自己的提议。
5. 每次提议、批准、拒绝或撤回产生新修订及审计快照。后续再次提议回到待复核，历史批准不会自动覆盖新修订。

`requires_numeric_review=true` 是 OCR 解析事实，不因某段批准而修改。批准状态只适用于其绑定的段落、原件版本与本次修订。当前复核层不会替换检索文本；需要重新索引不同内容时应登记新的不可变文档版本。

## 定位与资源边界

- PDF.js 与 worker 随应用本地打包，只有用户打开对照后才加载。不会把 PDF 发送给外部预览服务。
- 原件最多 50 MiB、200 页；仅渲染当前页，画布受总像素、单边尺寸及超时限制。切换或关闭时取消下载和渲染并销毁 worker。
- 高亮使用解析记录的页尺寸与 PDF 页面几何。现有定位契约未携带旋转、非零裁剪原点的映射证明；这些页面展示真实 PDF，并明确只定位到页。无法确认映射时不画猜测的框。
- `table_region` 表示整个表格区域；即使记录了行列，也不能称为精确单元格框。
- 浏览器访问对象存储需要该部署的受控 CORS 配置。授权链接短时有效，不记录或公开其签名参数。

包体检查保留原应用的 2700 KiB 总量、675 KiB 单块和最多一个大于 500 KiB 的块限制。新增复核资源单独受限：三个按需界面块合计 50 KiB、PDF 核心 450 KiB、worker 1200 KiB。检查实际构建 manifest 的动态依赖关系，并扫描全部静态 JavaScript（含 chunks 目录外的 worker）；未知文件仍计入原应用。浏览器回归另外验证打开对照前不会请求 PDF 核心或 worker，不能仅靠文件名获得预算例外。

## API 和持久化

数据库迁移为 `0033_knowledge_numeric_review`。`knowledge_numeric_reviews` 保存当前状态，`knowledge_numeric_review_events` 保存追加历史；事件表拒绝 SQL UPDATE/DELETE。不要在未备份的实际数据库执行降级，降级会移除复核记录。

| 方法 | API（前端使用 `/api/backend` 代理）                      | 用途                                                                      |
| ---- | -------------------------------------------------------- | ------------------------------------------------------------------------- |
| GET  | `/api/v1/knowledge/passages/{passage_id}/numeric-review` | 来源绑定、当前状态、权限和历史；`limit` 1–50，`cursor` 为排他的修订号上界 |
| POST | 同上                                                     | 提议数值修正或原值确认；需 `Idempotency-Key`                              |
| POST | 同上加 `/decision`                                       | `approve`、`reject` 或 `withdraw`；需 `Idempotency-Key`                   |

两个写接口都携带当前 `expected_revision` 和 GET 返回的五项 `source_binding`：文档版本、原件 SHA、原文 SHA、解析器版本及定位 SHA。首次提议 revision 为 0；所有数字偏移为 Unicode code point，不是 JavaScript UTF-16 下标。数值保存为字符串，以保留正负号、小数尾零与科学计数法。

写请求先核对当前角色、数据域、文档范围与来源身份，再读取幂等收据。相同主体/命令/目标/key 和相同请求可重放；不同请求或陈旧修订返回 409。状态、历史、领域事件及收据在同一事务提交；审批前还会重新核对原件字节。GET 需要读审计准入，不把审计故障当作成功。

网络响应不明时保留原提交内容和 key，只允许显式核验同一提交。当前页面会话内关闭、重开或切换段落仍按主体和来源身份保留该命令；完整刷新页面会结束这份内存状态。读写前重新确认当前登录主体，身份变化不发送旧主体的命令。权限拒绝不能自动换 key；修订冲突需要重新读取并由用户核对。旧收据可以反映历史修订，成功后应 GET 当前状态再展示最新权限。

## 验证入口及结论边界

后端定向测试包含实际 SQLite/API 的纠错、独立复核、角色/范围、同键重放、版本漂移、并发、事务回滚、原文恒等及追加历史约束。浏览器 fixture 单独验证实际 PDF 字节渲染、定位、错误状态、响应不明重试和布局；fixture 不等于真实 PostgreSQL/MinIO。

完整 `--scenario document` 在既有上传/OCR/索引/worker 中断恢复场景中增加：真实 PDF 渲染与哈希校验、错误数值提议被独立拒绝、原值确认与独立批准、重放/修订冲突/越权拒绝及重新打开后的持久状态。数据库证据脚本从真实记录重算历史 SHA 并核对四次修订、四份收据和四个领域事件。合成扫描件的正确数值不会被错误修正后冒称通过。

当前验证进度及未验证的外部服务见 [执行进度](../EXECUTION_PROGRESS.md)。实现了场景脚本不表示该场景已经运行通过；远端 CI、正式发布与真实现场精度以各自证据为准。
